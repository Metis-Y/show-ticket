# 08 抢票入口防护：令牌桶限流

> 状态：已实现。抢票接口入口用 Redis Lua 令牌桶限流，挡开售瞬间洪峰。
> （抢票凭证方案已放弃——它防脚本直连，但防不了「多账号 + 换 IP」的有组织黄牛，价值有限，见 §6）

## 1 目标

抢票接口开售瞬间会被洪峰打，入口此前是裸的。加一层令牌桶限流：允许突发、限制均速，超限快速失败，不给下游 Redis/MQ/DB 加压。

## 2 技术选型（为什么不用 X）

| 决策点 | 选型 | 为什么不用 X |
| --- | --- | --- |
| 算法 | **令牌桶** | 固定/滑动窗口不允许突发；漏桶完全平滑、消灭突发。秒杀要「允许 burst、限均速」 |
| 落地 | **Redis Lua**（rate_limit.lua） | 本地 Guava 单机有效、多实例不一致；Redis Lua 与 grab.lua 一致 |
| 接入 | **注解切面**（@RateLimit + RateLimitAspect） | 横切、可复用；拦截器是等价更轻替代 |

## 3 实现

- `resources/rate_limit.lua`：令牌桶原子脚本（按时间补发 + 判断 + 扣令牌），桶空返回 0；
- `utils/RateLimit.java` + `utils/RateLimitAspect.java`：注解 + 切面，桶空返回「系统繁忙，请稍后重试」；
- `controller/TicketOrderController.grabTicket` 挂 `@RateLimit(capacity = 500, rate = 500)`；
- key：`show-ticket:rate:grab`（`RedisConstants.RATE_LIMIT_KEY`）。

## 4 容量 / 速率怎么定

按**实测稳态容量（~950 req/s）的 7 成**取整起步，当前 `capacity=rate=500` 是占位值，压测后按需调。**不拍脑袋。**

## 5 压测口径

1. 被限流拒绝的请求**单独统计**，不与「售罄（业务拒绝 200）/ 系统错误」混；
2. 限流要**单独测**：到达速率高于令牌补发速率才触发，否则测了等于没测；
3. 别和「异步 vs 同步落库」的对照掺一起——多一个变量；
4. 限流给抢票接口多一次 Redis 往返（~0.5ms），重压测基线会略高。

## 6 v1 边界（不做 / 放弃）

- **抢票凭证**：已放弃——防脚本直连但防不了有组织黄牛；
- 按用户 / 按 IP 分维度限流（v1 只做接口级全局令牌桶）；
- 配置热改限流参数；
- HMAC 地址加密、设备指纹、第三方验证码（这些才是防黄牛的活，demo 不做）。
